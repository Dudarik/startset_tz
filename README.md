# Стикеры на холсте (Vue 3 + Pinia + TypeScript + Vite)

#### Деплой

[startset_tz](https://dudarik.github.io/startset_tz/ 'gh-pages')

#### Установка зависимостей

```bash
npm install
```

#### Запуск в режиме разработки

```bash
npm run dev
```

## Введение

Необходимо реализовать интерактивный холст со стикерами по аналогии с сервисом Miro.

Требуются только прямоугольные элементы процессов (в данном примере они с синей границей) и сами стикеры (подсказки). Клетки делать также не обязательно, в данном ТЗ в этом нет необходимости.

## Функциональные требования

### Холст

Реализовать фиксированный холст, на котором:

- фиксированный размер (например 1200×800)
- внутри размещаются элементы
- скролл не требуется
- холст - обычный контейнер

### Процессы (блоки)

На холсте должны присутствовать несколько статических блоков (в данном задании договоримся называть их “процессами”).
**Важно**:

- процессы можно захардкодить (не нужно строить backend или динамическое создание блоков процессов. Их координаты и размеры можно задать прямо в коде. Достаточно, чтобы на холсте были несколько элементов (блоков), которые занимают место (2-3 будет достаточно).
- процессы нельзя перекрывать стикерами.

Цель - реализовать логику пересечений. Блоки процессов можно реализовать без перемещения.

## Создание стикера

Пользователь может:

- создать новый стикер
- ввести текст
- увидеть его на холсте

## Автомасштабирование текста (ключевое требование)

По аналогии с miro, стикер можно ввести в режим редактирования и в готовом стикере на холсте изменять текст. Размер шрифта должен автоматически изменяться в зависимости от количества символов. Размер шрифта должен подбираться динамически на основе доступного пространства (через измерение DOM). Простая зависимость от количества символов не считается корректной реализацией.

### Ожидаемое поведение

- мало текста - шрифт крупнее
- много текста - шрифт уменьшается
- текст всегда помещается внутри стикера
- текст не выходит за границы

## Перемещение стикера

Стикер можно перетаскивать мышью по холсту. Стикер не должен выходить за границы холста.

### Ограничение (важно)

Стикер не должен перекрывать процессы, но может перекрывать другие стикеры.

### Z-index

Активный (перетаскиваемый) стикер должен отображаться поверх остальных. После завершения перетаскивания порядок может сохраняться.

### Ресайз стикера (обязательно)

Стикер должен поддерживать изменение размера через растягивание за границу стикера. Ожидается resize через видимые drag-handles (угол или стороны на усмотрение кандидата). Минимальный размер стикера на усмотрение кандидата, но стикер не должен схлопываться до нуля.
Текст корректно адаптируется под новый размер. Размер шрифта должен пересчитываться при изменении текста и при изменении размеров стикера.

### Управление состоянием (Pinia)

Для хранения состояния приложения был выбран Pinia.

#### Обоснование:

- Список стикеров, а так же их координаты должны быть доступны для (собственно)стикеров, компонентов холста, панелей инструментов, etc. Позволяет избавиться от props drilling.
- Легко добавить функционал в будущем (например, сохранение в backend, localstorage) без переписывания архитектуры.
